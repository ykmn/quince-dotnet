# Айва (Quince.Service)

Многоканальный аудиологгер — веб-приложение на ASP.NET Core (Blazor Server), устанавливаемое как служба Windows. Версия: см. `CHANGELOG.md` (текущая — `0.00.016`). Лицензия: GNU GPL v3 (`LICENSE.md`) — бесплатное opensource-приложение.

## Требования

- Для разработки/сборки: .NET 8 SDK.
- Для запуска у пользователя: **ничего дополнительно ставить не нужно** — с версии 0.00.005 публикуемая сборка самодостаточная (self-contained, `win-x64`) и включает весь нужный .NET-рантайм рядом с `Quince.Service.exe`. Нужна только Windows x64.
- Аудио-движок использует бандлированные `ffmpeg.exe`/`ffprobe.exe` (`Quince.Service/tools/`) и `bass.dll` (рядом с `Quince.Service.exe`) — тоже ничего скачивать отдельно не нужно для запуска. Про лицензионные условия `bass.dll` (важно, если приложение используется коммерчески) см. «Сторонние бинарные компоненты» ниже.

## Запуск в разработке

Из папки репозитория:

```
dotnet run --project .\Quince.Service\
```

или из папки `Quince.Service\`:

```
dotnet run
```

Оба варианта равнозначны: рабочая директория запущенного процесса при `dotnet run` — это всегда папка проекта, а `config/`/`log/` резолвятся относительно папки скомпилированного приложения (см. ниже), а не от того, откуда вызван `dotnet`.

Приложение слушает `http://localhost:5000` (см. `appsettings.json`, ключ `Urls`).

## Сборка и публикация

```
dotnet build .\Quince.Service\
dotnet publish .\Quince.Service\ -c Release -o .\release\<версия>
```

Проект настроен на self-contained публикацию под `win-x64` (`RuntimeIdentifier`/`SelfContained` в `Quince.Service.csproj`) — команда `dotnet publish` выше сама кладёт в `release\<версия>\` весь нужный .NET-рантайм и все сторонние бинарники (`ffmpeg.exe`, `ffprobe.exe`, `bass.dll` — см. «Сторонние бинарные компоненты»), отдельно ничего скачивать не нужно. Папка публикации — около 280 МБ (из них ~97 МБ `ffmpeg.exe` и ~85 МБ `ffprobe.exe`, `bass.dll` — не более 200 КБ; сам .NET-рантайм добавляет ещё ~95 МБ поверх framework-dependent варианта, который требовал установленного на целевой машине ASP.NET Core Runtime 8.0).

## Расположение данных

Все рабочие данные приложения лежат **рядом со скомпилированным `Quince.Service.exe`** (не зависят от того, как и откуда запущен процесс — важно для установки как службы Windows, где рабочая директория обычно не совпадает с папкой приложения):

- `config/` — YAML-конфиги каналов и `app.yaml` (настройки приложения). Путь настраивается ключом `ConfigDir` в `appsettings.json` (по умолчанию `"config"`).
- `log/` — файлы журнала, по одному на день. Путь настраивается ключом `LogDir` в `appsettings.json` (по умолчанию `"log"`).
- `recording/` — записанные аудиофайлы по каналам (создаётся движком записи; на момент версии `0.00.002` реализовано для каналов `source.type: stream` — для `soundcard` движок ещё не реализован).

Оба пути (`config`, `log`) можно также задать абсолютными — тогда они не привязываются к папке приложения.

## Конфигурация канала (`config/*.yaml`)

Пример (см. реальные примеры в `Quince.Service/config/`):

```yaml
name: Ретро FM HLS
source:
  type: stream            # stream | soundcard
  url: https://.../playlist.m3u8
  stream_type: hls         # hls | icecast | icecast_mp3
  device_name: ''          # для type: soundcard
  device_index: -1
  device_uid: ''
  allow_http: false
  allow_invalid_ssl: false
  metadata_url: ''                     # '' | 'icy' | JSON-эндпоинт — можно вписать вручную или подставить кнопкой «Определить»
  reconnect_delay_seconds: 3
input_format:
  sample_rate: 0
  bit_depth: 0
  channels: 0
  bitrate: 0
  codec: ''
output_format:
  mode: original            # original | custom — см. пояснение ниже
  file_format: aac          # используется только при mode: custom — mp3 | aac | wav
  sample_rate: 48000
  bit_depth: 16
  channels: 2
  bitrate_kbps: 96
save_path: D:\recording\Retro
date_folder_format: YYYY-MM-DD
file_name_format: hh-mm-ss
file_duration_seconds: 600
record_audio: true
retention_days: 30
auto_start: false
silence_detector:
  enabled: false
  threshold_dbfs: -60.0
  trigger_seconds: 3.0
  resume_seconds: 1.0
metadata_path: ''
```

Файлы без поля `name` (например `app.yaml`) не считаются каналами и не отображаются в списке.

**`output_format.mode: original`** («Как во входном потоке» в форме редактирования) сохраняет звук в формате, соответствующем источнику, а не заданному вручную `file_format` (это поле в этом режиме игнорируется): звуковая карта → WAV PCM с той же частотой дискретизации и числом каналов, с которыми шёл захват; HLS-поток → AAC; Icecast/Icecast-MP3 → MP3. `mode: custom` включает ручной выбор `file_format`/битрейта/частоты/каналов ниже по списку.

## Управление каналами из веб-интерфейса

- **➕ Новый канал** (пункт бургер-меню) и **✎** на карточке канала открывают одну и ту же форму редактирования (все поля YAML-схемы выше, у каждого — всплывающая подсказка). Сохранение пишет файл в `config/`. Кнопка **Обзор…** у поля «Папка сохранения» пытается открыть системный диалог выбора папки Windows на компьютере, где выполняется процесс приложения (для интерактивного запуска — `dotnet run`/exe с обычного рабочего стола); если процесс работает без интерактивного рабочего стола (служба Windows) или диалог по какой-то причине не открылся, используется резервный вариант — встроенный браузер папок по файловой системе сервера. Папка сохранения создаётся автоматически, если её ещё нет; ошибка показывается только если диск или сетевой путь реально недоступны. Для источника «Звуковая карта» доступен выпадающий список обнаруженных устройств записи с кнопкой **🔄 Обновить** (полезно после подключения/отключения USB-микрофона) — выбор из списка подставляет UID и имя устройства; сопоставление в движке записи ведётся по UID (устойчив к переподключению USB), а не по индексу устройства (может меняться). Список исключает WASAPI loopback-устройства (запись с выходов), оставляя только настоящие входы; у некоторых виртуальных аудиокабелей (например VB-Audio Virtual Cable) сама записываемая сторона в имени содержит слово «Output» (`CABLE Output`) — это особенность именования конкретной программы, не ошибка фильтра. Для источника «Поток» поле «URL метаданных / режим» редактируется вручную (значения: пусто/`icy`/JSON-эндпоинт) или заполняется кнопкой **«Определить»** — она сразу показывает, найдены ли метаданные (ICY или JSON) по текущим (ещё не сохранённым) URL/типу потока и подставляет результат в поле, без сохранения канала.
- На карточке канала в строке заголовка — три круглых индикатора: статус записи (серый — не пишет, зелёный — пишет, жёлтый мигающий — переподключение), индикатор метаданных (только для источника «Поток»: серый — режим метаданных не настроен, голубой — настроен), и индикатор наличия сигнала (зелёный — звук есть, красный — тишина, по мгновенному True Peak; не зависит от отдельно настраиваемого ниже «Детектора тишины», который по умолчанию выключен).
- **⧉** — клонирует канал (новое имя вида «Название (копия)», автозапуск клона всегда выключен, чтобы не запустить два движка на один и тот же источник одновременно).
- **✕** — удаляет канал (с подтверждением). Удаляется только YAML-конфиг; уже записанные аудиофайлы не трогаются.
- **📊 Индикаторы**: на карточке канала открывает панель, раздвигающую страницу (список каналов сужается, а не перекрывается), с вертикальными сегментированными (зелёная/жёлтая/красная зоны по настройкам) шкалами True Peak L/R и LUFS (Momentary/Short-term/Integrated) и гониометром (стереофазовым осциллографом) фиксированного размера внизу. У всех пяти индикаторов есть пиковый максимум («макс: …») — держится с момента запуска канала, клик по любому из них сбрасывает все пять сразу. При остановке записи текущие значения обнуляются, максимум — нет.
- **🔄 Обновить конфигурацию** — пересканирует `config/` и обновляет список каналов без перезапуска приложения (подхватывает файлы, добавленные/изменённые/удалённые вручную). Результат (сколько добавлено/изменено/удалено) показывается в статусной строке под фильтром на главной странице — там же отображаются результаты запуска/остановки всех каналов и уведомление о перезапуске.
- **▶️/⏹️ Запустить/остановить запись всех каналов** — массовый старт/стоп для всех каналов, для которых реализован движок записи (`stream`, `soundcard`).
- **🔁 Перезапуск приложения** — останавливает все каналы и завершает процесс приложения. Настоящий автоматический перезапуск зависит от того, как приложение запущено: под службой Windows с настроенным восстановлением (вкладка «Recovery» в свойствах службы) служба перезапустится сама; при запуске через `dotnet run`/exe процесс нужно будет запустить заново вручную.

## Метаданные потока (название трека)

Реализовано в точности как в предшественнике этого проекта (десктопная версия на Python/Qt) — тот же режим определения, тот же формат хранения:

`source.metadata_url` — режим, а не произвольный URL: редактируется вручную в поле «URL метаданных / режим» или подставляется кнопкой **«Определить»** в диалоге редактирования канала (см. выше):
- `"icy"` — метаданные читаются напрямую из аудиопотока по протоколу ICY (`Icy-MetaData: 1`, блок `StreamTitle='Artist - Title'`); используется для `stream_type: icecast`/`icecast_mp3`. Разрыв соединения не приводит к остановке — переподключение с нарастающей паузой (1, 2, 4, 8, 16, 30 с).
- любое другое непустое значение — режим метаданных HLS: при каждом старте канала заново определяется JSON-эндпоинт метаданных (перебираются `{папка_плейлиста}/metadata.json?format=fmgid&subformat=small`, `{папка_плейлиста}/metadata.json`, `/metadata.json` в корне хоста; распознаются форматы `{"fmgid": {...}}`, плоские поля `title`/`name`/`song`/`artist`, либо строка вида `"Артист - Трек"` в полях `now_playing`/`current`/`stream_title`) и опрашивается раз в 5 секунд; поиск эндпоинта повторяется до 3 раз с паузой 3 с (чтобы разовая сетевая заминка при старте не отправила канал в резерв навсегда), и только если ни одна из попыток не откликнулась — делается одна попытка вытащить ID3-теги (`title`/`artist`) прямо из потока через бандлированный `ffprobe.exe` — без повторов.
- `""` (по умолчанию) — метаданные не собираются.

Полученные события пишутся построчно в CSV-файл `{metadata_path либо, по умолчанию, {save_path}\meta\}\{YYYY-MM-DD}.csv` (кодировка UTF-8 с BOM, все поля в кавычках) с колонками `EventTime, ElemName, ElemArtist, ElemClass, ElemLength` — строка для трека дописывается только когда придёт СЛЕДУЮЩЕЕ событие метаданных (тогда становится известна длительность предыдущего трека, `ElemLength`, формат `Ч:ММ:СС.ммм`/`М:СС.ммм`) либо когда канал останавливается (тогда недописанная строка сбрасывается на диск без `ElemLength`). **Важно**: пока трек не сменился и канал не остановлен, файл `.csv` за сегодня ещё не появится — это не баг, а отложенная запись строки (чтобы знать её длительность), так и было задумано в оригинале.

## Журнал (`log/`)

- Новый файл каждый день: `log/YYYY-MM-DD.log`.
- Уровень логирования настраивается через `log_level` в `app.yaml` (DEBUG/INFO/WARNING/ERROR).
- Старые файлы удаляются автоматически по истечении `log_retention_days` дней (по умолчанию 30).
- Формат строки: `YYYY-MM-DD HH:MM:SS.mmm [LEVEL] [channel_name] сообщение` — `[channel_name]` заменяется на `[-]` для сообщений уровня приложения, не привязанных к конкретному каналу.

## Сторонние бинарные компоненты

Всё нужное для работы бандлируется прямо в `release/<версия>/` — отдельно ничего скачивать и ставить не нужно. Три сторонних бинарника:

| Файл | Расположение | Источник | Лицензия |
|---|---|---|---|
| `ffmpeg.exe` | `Quince.Service/tools/` | официальная статическая сборка [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) (`essentials_build`) | GPL/LGPL (FFmpeg) — свободное использование, в т.ч. коммерческое |
| `ffprobe.exe` | `Quince.Service/tools/` | сборка того же семейства gyan.dev `essentials_build` | GPL/LGPL (FFmpeg) — свободное использование, в т.ч. коммерческое |
| `bass.dll` | рядом с `Quince.Service.exe` (`Quince.Service/native/bass.dll` в исходниках, копируется в корень публикации) | [un4seen Developments](https://www.un4seen.com/) | **проприетарная, см. ниже** |

**Лицензия BASS.** Библиотека `bass.dll` (используется `ManagedBass` в `SoundcardCapture` для захвата со звуковых карт) распространяется un4seen Developments **бесплатно только для некоммерческого использования** (freeware/shareware/образовательные и т.п. проекты). Айва распространяется как бесплатное opensource-приложение (см. `LICENSE.md`, GNU GPL v3) — это подпадает под бесплатный уровень лицензии BASS. Если условия использования когда-нибудь изменятся на коммерческие (например, встраивание в платный продукт), для `bass.dll` отдельно потребуется приобрести регистрацию — см. условия и цены на [un4seen.com/bass.html](https://www.un4seen.com/bass.html) (раздел лицензирования); сама по себе сборка Quince.Service такую регистрацию не подтверждает и не заменяет.

Обновление/замена любого из трёх файлов — просто перезапись файла тем же именем в той же папке (все три подключаются по пути, а не встраиваются в сборку .NET), рестарт приложения подхватит новую версию.

## Известные ограничения (по состоянию на 0.00.016)

- Изредка диалог редактирования канала может закрыться сам во время работы с ним (похоже на потерю Blazor Server circuit и перезагрузку страницы браузером). Точная причина не подтверждена — нет браузерного инструмента для интерактивной отладки в среде разработки на момент этой доработки. Один вероятный сценарий (исключение при сохранении конфига, который тем временем исчез) устранён в 0.00.006; если проблема повторится, полезно проверить `log/YYYY-MM-DD.log` на ERROR-записи в момент закрытия и консоль браузера (F12) на ошибки соединения.
- Кнопка **Обзор…** пытается открыть системный диалог выбора папки на машине, где выполняется процесс приложения, а не на компьютере пользователя, открывшего страницу в браузере — если веб-интерфейс администрируется удалённо (не с той же машины, где крутится служба), диалог покажется «не туда», и стоит либо использовать резервный встроенный браузер папок (появляется автоматически, если системный диалог не смог открыться), либо просто печатать путь в поле вручную.
- Папка `config/RP/` (~150 доп. станций) не читается рекурсивно — обрабатываются только файлы верхнего уровня `config/`.

```
Quince.Service/
  Audio/             — движок записи: StreamCapture/SoundcardCapture (IAudioCapture), AudioWriter, LevelMeter, SilenceDetector, ChannelEngine; метаданные — IcecastMetadataReader/HlsMetadataReader (IMetadataReader) + MetadataWriter (CSV)
  Configuration/     — модели и загрузчики YAML-конфигов (ChannelConfig, AppConfig)
  Services/          — ChannelManager (CRUD каналов), AudioEngineManager, AppSettingsService, ChannelUiState, MetadataDetectionService, NativeFolderPicker, файловый логгер, форматирование для UI
  Pages/             — Blazor-страницы и layout (топбар, бургер-меню, карточки каналов, диалоги редактирования/индикаторов/настроек)
  config/            — YAML-конфиги (копируются в выходную папку сборки)
  native/            — bass.dll (копируется в корень публикации, см. «Сторонние бинарные компоненты»)
  tools/             — ffmpeg.exe, ffprobe.exe (копируются в выходную папку сборки)
  wwwroot/           — статика: стили, шрифты, иконка
```
