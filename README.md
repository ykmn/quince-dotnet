# Айва (Quince.Service)

Многоканальный аудиологгер — веб-приложение на ASP.NET Core (Blazor Server), устанавливаемое как служба Windows. Версия: см. `docs/CHANGELOG.md` (текущая — `1.00.000`). Лицензия: GNU GPL v3 (`LICENSE.md`) — бесплатное opensource-приложение.

## Требования

- Для разработки/сборки: .NET 8 SDK.
- Для запуска у пользователя: **ничего дополнительно ставить не нужно** — с версии 0.00.005 публикуемая сборка самодостаточная (self-contained, `win-x64`) и включает весь нужный .NET-рантайм рядом с `Quince.Service.exe`. Нужна только Windows x64.
- Аудио-движок использует бандлированные `ffmpeg.exe`/`ffprobe.exe` (`Quince.Service/tools/`) для сетевых потоков и NAudio (управляемая библиотека, MIT) для захвата со звуковой карты — тоже ничего скачивать отдельно не нужно для запуска.

## Запуск в разработке

Из папки репозитория:

```
dotnet run --project .\Quince.Service\
```

или из папки `Quince.Service\`:

```
dotnet run
```

Оба варианта равнозначны: рабочая директория запущенного процесса при `dotnet run` — это всегда папка проекта, а `config/`/`log/` резолвятся относительно папки скомпилированного приложения (см. ниже), а не от того, откуда вызван `dotnet`.

Приложение слушает `http://localhost:5000` (см. `appsettings.json`, ключ `Urls`).

## Сборка и публикация

```
dotnet build .\Quince.Service\
dotnet publish .\Quince.Service\ -c Release -o .\release\<версия>
```

Проект настроен на self-contained публикацию под `win-x64` (`RuntimeIdentifier`/`SelfContained` в `Quince.Service.csproj`) — команда `dotnet publish` выше сама кладёт в `release\<версия>\` весь нужный .NET-рантайм и сторонние бинарники (`ffmpeg.exe`, `ffprobe.exe` — см. «Сторонние бинарные компоненты»), отдельно ничего скачивать не нужно. Папка публикации — около 280 МБ (из них ~97 МБ `ffmpeg.exe` и ~85 МБ `ffprobe.exe`; сам .NET-рантайм добавляет ещё ~95 МБ поверх framework-dependent варианта, который требовал установленного на целевой машине ASP.NET Core Runtime 8.0). `SatelliteResourceLanguages` в `Quince.Service.csproj` ограничен `en;ru` — сателлитные ресурсные сборки .NET/ASP.NET Core (локализованные тексты исключений фреймворка и т.п.) для остальных ~11 языков в публикацию не попадают.

## Установка как служба Windows

Приложение уже подготовлено для запуска как служба Windows (`Program.cs` вызывает `UseWindowsService(options => options.ServiceName = "QuinceAudioLogger")`, пакет `Microsoft.Extensions.Hosting.WindowsServices`) — рабочая директория службы (обычно `C:\Windows\System32`) роли не играет, все пути (`config/`, `log/`, `tools/`) резолвятся относительно папки, где лежит `Quince.Service.exe`, а не относительно текущей директории процесса.

1. Опубликуйте релиз (см. «Сборка и публикация» выше) в постоянную папку, например `C:\Quince\`.
2. Создайте службу (команда от имени администратора, кавычки вокруг пути к exe обязательны):
   ```
   sc.exe create QuinceAudioLogger binPath= "C:\Quince\Quince.Service.exe" start= auto DisplayName= "Айва (Quince) — аудиологгер"
   ```
3. Запустите службу:
   ```
   sc.exe start QuinceAudioLogger
   ```
4. Веб-интерфейс станет доступен по тому же адресу, что и при обычном запуске (`http://localhost:5000` — см. `appsettings.json`, ключ `Urls`).

Удаление службы:
```
sc.exe stop QuinceAudioLogger
sc.exe delete QuinceAudioLogger
```

Готовые bat-скрипты для тех же действий — `Quince.Service/tools/service-create.bat`, `service-start.bat`, `service-stop.bat`, `service-restart.bat`, `service-delete.bat`. Каждый сам проверяет права администратора и при необходимости перезапускает себя с UAC-запросом (`powershell Start-Process -Verb RunAs`) — отдельно запускать «от имени администратора» не нужно, достаточно обычного двойного клика.

Обновление версии под службой: остановить службу (`sc.exe stop QuinceAudioLogger` — в приложении нет собственного пункта меню для перезапуска), заменить файлы новой публикацией, запустить снова (`sc.exe start QuinceAudioLogger`) — `config/`/`log/` при этом не трогаются, так как лежат рядом с exe, а не внутри самой службы.

## Расположение данных

Все рабочие данные приложения лежат **рядом со скомпилированным `Quince.Service.exe`** (не зависят от того, как и откуда запущен процесс — важно для установки как службы Windows, где рабочая директория обычно не совпадает с папкой приложения):

- `config/` — `settings.yaml` (настройки приложения), опционально `ldap.yaml`/`users.yaml`/`secret.yaml`/`sessions.yaml` (авторизация, см. «Авторизация» ниже); YAML-конфиги каналов лежат в подпапке `config/stations/`. Путь настраивается ключом `ConfigDir` в `appsettings.json` (по умолчанию `"config"`). При обновлении с версии до 0.00.061 старый `config/app.yaml` и лежавшие прямо в `config/` конфиги каналов переносятся в новый вид автоматически при первом запуске.
- `log/` — файлы журнала, по одному на день. Путь настраивается ключом `LogDir` в `appsettings.json` (по умолчанию `"log"`).
- `recording/` — записанные аудиофайлы по каналам (создаётся движком записи; на момент версии `0.00.002` реализовано для каналов `source.type: stream` — для `soundcard` движок ещё не реализован).

Оба пути (`config`, `log`) можно также задать абсолютными — тогда они не привязываются к папке приложения.

`config/` — машино-специфичные реальные данные (реальные станции, реальные учётные данные для LDAP) и поэтому в git не попадает (`.gitignore`, по образцу apricot2). Для первого запуска на новой машине — скопируйте `config.demo/` (лежит в репозитории и в каждой публикации, см. «Структура проекта» ниже) в `config/` и отредактируйте под себя: удалите/замените пример станции в `stations/`, при необходимости настройте `ldap.yaml`/`users.yaml`/`secret.yaml` (см. «Авторизация» ниже). Без этого шага приложение всё равно запустится — `config/` создастся пустым автоматически, среди станций будет пусто и авторизация будет выключена (нет `ldap.yaml` — нет и файла-переключателя).

## Конфигурация канала (`config/stations/*.yaml`)

Пример (см. реальные примеры в `Quince.Service/config/stations/`):

```yaml
name: Ретро FM HLS
source:
  type: stream            # stream | soundcard
  url: https://.../playlist.m3u8
  stream_type: hls         # hls | icecast | icecast_mp3
  device_name: ''          # для type: soundcard
  device_index: -1
  device_uid: ''
  allow_http: false
  allow_invalid_ssl: false
  metadata_url: ''                     # '' | 'icy' | JSON-эндпоинт — можно вписать вручную или подставить кнопкой «Определить»
input_format:
  sample_rate: 0
  bit_depth: 0
  channels: 0
  bitrate: 0
  codec: ''
output_format:
  mode: original            # original | custom — см. пояснение ниже
  file_format: aac          # используется только при mode: custom — mp3 | aac | wav
  sample_rate: 48000
  bit_depth: 16
  channels: 2
  bitrate_kbps: 96
save_path: D:\recording\Retro
date_folder_format: YYYY-MM-DD
file_name_format: hh-mm-ss
file_duration_minutes: 10
record_audio: true
retention_days: 30
auto_start: false
silence_detector:
  enabled: false
  threshold_dbfs: -60.0
  trigger_seconds: 3.0
  resume_seconds: 1.0
metadata_path: ''
```

Файлы без поля `name` не считаются каналами и не отображаются в списке (в частности, поэтому `settings.yaml`/`ldap.yaml`/`users.yaml`/`secret.yaml`/`sessions.yaml` намеренно лежат уровнем выше — в `config/`, а не в `config/stations/`).

Пауза между попытками переподключения при обрыве потока/устройства — общая для всех каналов настройка (`reconnect_delay_seconds` в `settings.yaml`, см. «Настройки приложения» ниже), а не поле в конфиге отдельного канала.

**`output_format.mode: original`** («Как во входном потоке» в форме редактирования) сохраняет звук в формате, соответствующем источнику, а не заданному вручную `file_format` (это поле в этом режиме игнорируется): звуковая карта → WAV PCM с той же частотой дискретизации и числом каналов, с которыми шёл захват; HLS-поток → AAC; Icecast/Icecast-MP3 → MP3. `mode: custom` включает ручной выбор `file_format`/битрейта/частоты/каналов ниже по списку.

## Управление каналами из веб-интерфейса

- **➕ Новый канал** (пункт бургер-меню) и **✎** на карточке канала открывают одну и ту же форму редактирования (все поля YAML-схемы выше, у каждого — всплывающая подсказка), под полем «Название» разбитую на три вкладки — **Вход** (тип источника и всё специфичное для него: URL/тип потока/HLS-индекс/HTTP/SSL/метаданные для «Поток», список устройств/UID/имя для «Звуковая карта»), **Выход** (папка сохранения, форматы имени файла/папки по дате, длительность файла, срок хранения, «Вести запись», «Автозапуск», формат вывода) и **Детектор тишины** (порог/срабатывание/возобновление). Если проверка при сохранении находит ошибку в поле на неактивной вкладке (например, не указан URL потока, пока открыта вкладка «Выход»), диалог сам переключается на нужную вкладку вместе с сообщением об ошибке. Сохранение пишет файл в `config/`. Диалог закрывается только кнопками «Сохранить»/«Отмена» — клик по затемнённому фону не закрывает форму (это специально: раньше клик мимо формы закрывал её даже случайно, например если выделение текста в поле мышью заканчивалось за пределами окна). Кнопка **Обзор…** у поля «Папка сохранения» всегда открывает встроенный браузер папок по файловой системе **сервера** (машины, где выполняется процесс Quince.Service), а не компьютера, с которого открыта страница в браузере, — это осознанный выбор, а не хак: показать реальный диалог Windows с сервера в браузере клиента вообще невозможно. Папка сохранения создаётся автоматически, если её ещё нет; ошибка показывается только если диск или сетевой путь реально недоступны. Для источника «Звуковая карта» доступен выпадающий список обнаруженных устройств записи с кнопкой **🔄 Обновить** (полезно после подключения/отключения USB-микрофона) — выбор из списка подставляет UID и имя устройства; сопоставление в движке записи ведётся по UID (устойчив к переподключению USB), а не по индексу устройства (может меняться). Список исключает WASAPI loopback-устройства (запись с выходов), оставляя только настоящие входы; у некоторых виртуальных аудиокабелей (например VB-Audio Virtual Cable) сама записываемая сторона в имени содержит слово «Output» (`CABLE Output`) — это особенность именования конкретной программы, не ошибка фильтра. Для источника «Поток» поле «URL метаданных / режим» редактируется вручную (значения: пусто/`icy`/JSON-эндпоинт) или заполняется кнопкой **«Определить»** — она сразу показывает, найдены ли метаданные (ICY или JSON) по текущим (ещё не сохранённым) URL/типу потока и подставляет результат в поле, без сохранения канала.
- **▶/⏹ Прослушать канал** на карточке (рядом с Старт/Стоп) стримит живое аудио канала в браузер — играет через **аудиовыход по умолчанию на компьютере, за которым сидит оператор** (не сервера), независимо от того, ведётся ли запись на диск и запущен ли канал вообще. Сервер кодирует поток в MP3 через бандлированный `ffmpeg.exe` и отдаёт его по HTTP (`/api/playback/stream/{канал}`) скрытому `<audio>`-элементу страницы — выбор конкретного устройства воспроизведения на компьютере оператора пока недоступен: `HTMLMediaElement.setSinkId()` браузеры разрешают только в secure context (HTTPS, либо `localhost`), а приложение сейчас слушает обычный HTTP для доступа по сети (см. «Установка как служба Windows» выше про `Urls`) — это в бэклоге. Если канал ещё не запущен, нажатие ▶ временно запускает его конвейер захвата только для прослушивания и останавливает обратно при нажатии ⏹ — если канал уже писался по-настоящему, запись не прерывается. Одновременно можно слушать только один канал; запуск прослушивания другого канала останавливает предыдущий. Для HLS-потоков старт звука после нажатия ▶ занимает заметно больше времени, чем для Icecast — это ожидаемо: HLS доставляется сегментами по несколько секунд, а не непрерывным соединением (см. `-live_start_index -1`/`-fflags nobuffer` в описании `StreamCapture` ниже).
- На карточке канала в строке заголовка — три круглых индикатора:
  - **Статус записи**: серый — не пишет, зелёный — пишет (в том числе во время автоматического переподключения — попытка отражается отдельной надписью «Реконнект #N» рядом с названием), красный — канал остановился сам после того, как исчерпал предел попыток переподключения (см. «Настройки приложения» ниже) — держится, пока канал не будет запущен заново.
  - **Метаданные** (только для источника «Поток»): фиолетовый — метаданные сейчас поступают, серый — режим метаданных не настроен ИЛИ настроен, но ничего не поступает.
  - **Звук** (для «Поток» и «Звуковая карта»): зелёный — звук есть, красный — сработал детектор тишины, серый — запись не идёт. Если детектор тишины в настройках канала выключен, этот индикатор во время записи всегда зелёный.
- **⧉** — клонирует канал после подтверждения в диалоге (новое имя вида «Название (копия)», автозапуск клона всегда выключен, чтобы не запустить два движка на один и тот же источник одновременно).
- **✕** — удаляет канал (с подтверждением). Удаляется только YAML-конфиг; уже записанные аудиофайлы не трогаются.
- **📊 Индикаторы**: на карточке канала открывает панель, раздвигающую страницу (список каналов сужается, а не перекрывается), с вертикальными сегментированными (зелёная/жёлтая/красная зоны по настройкам) шкалами True Peak L/R и LUFS (Momentary/Short-term/Integrated) и гониометром (стереофазовым осциллографом) фиксированного размера внизу. У всех пяти индикаторов есть пиковый максимум («макс: …») — держится с момента запуска канала, клик по любому из них сбрасывает все пять сразу. При остановке записи текущие значения обнуляются, максимум — нет.
- **🔄 Обновить конфигурацию** — пересканирует `config/stations/` и обновляет список каналов без перезапуска приложения (подхватывает файлы, добавленные/изменённые/удалённые вручную). Результат (сколько добавлено/изменено/удалено) показывается в статусной строке под фильтром на главной странице — там же отображаются результаты запуска/остановки всех каналов и уведомление о перезапуске.
- **▶️/⏹️ Запустить/остановить запись всех каналов** — массовый старт/стоп для всех каналов, для которых реализован движок записи (`stream`, `soundcard`).
- **🔁 Перезапуск приложения** — останавливает все каналы и завершает процесс приложения. Настоящий автоматический перезапуск зависит от того, как приложение запущено: под службой Windows с настроенным восстановлением (вкладка «Recovery» в свойствах службы) служба перезапустится сама; при запуске через `dotnet run`/exe процесс нужно будет запустить заново вручную.
- **🌐 Язык интерфейса (RU/EN)** — переключатель в бургер-меню, переключение мгновенное, без перезагрузки страницы. Весь текст интерфейса вынесен в `Quince.Service/i18n/ru.json`/`en.json` (`LocalizationService`), выбор сохраняется в `settings.yaml` (`ui_language`) и переживает перезапуск приложения. Журнал, метаданные треков и содержимое README.md не переводятся — локализация касается только интерактивного UI.

## Метаданные потока (название трека)

Реализовано в точности как в предшественнике этого проекта (десктопная версия на Python/Qt) — тот же режим определения, тот же формат хранения:

`source.metadata_url` — режим, а не произвольный URL: редактируется вручную в поле «URL метаданных / режим» или подставляется кнопкой **«Определить»** в диалоге редактирования канала (см. выше):
- `"icy"` — метаданные читаются напрямую из аудиопотока по протоколу ICY (`Icy-MetaData: 1`, блок `StreamTitle='Artist - Title'`); используется для `stream_type: icecast`/`icecast_mp3`. Разрыв ЭТОГО отдельного метаданных-соединения не приводит к остановке канала — переподключение с нарастающей паузой (1, 2, 4, 8, 16, 30 с), независимо от паузы/предела попыток самого аудиопотока (см. «Настройки приложения» ниже).
- любое другое непустое значение — режим метаданных HLS, и одновременно сам сохранённый JSON-эндпоинт (найденный ранее кнопкой «Определить»): при старте канала он пробуется первым напрямую, без повторного перебора кандидатов — это важно, когда JSON-эндпоинт живёт не в той же папке, что плейлист (например у станции путь плейлиста и путь метаданных используют разные числовые id потока). Только если этот URL не откликнулся (сменился/недоступен), эндпоинт заново определяется перебором кандидатов (`{папка_плейлиста}/metadata.json?format=fmgid&subformat=small`, `{папка_плейлиста}/metadata.json`, `/metadata.json` в корне хоста; распознаются форматы `{"fmgid": {...}}`, плоские поля `title`/`name`/`song`/`artist`, либо строка вида `"Артист - Трек"` в полях `now_playing`/`current`/`stream_title`); найденный (тем или другим способом) эндпоинт опрашивается раз в 5 секунд. Перебор кандидатов повторяется до 3 раз с паузой 3 с (чтобы разовая сетевая заминка при старте не отправила канал в резерв навсегда), и только если ни одна из попыток не откликнулась — делается одна попытка вытащить ID3-теги (`title`/`artist`) прямо из потока через бандлированный `ffprobe.exe` — без повторов.
- `""` (по умолчанию) — метаданные не собираются.

Полученные события пишутся построчно в CSV-файл `{metadata_path либо, по умолчанию, {save_path}\meta\}\{YYYY-MM-DD}.csv` (кодировка UTF-8 с BOM, все поля в кавычках) с колонками `EventTime, ElemName, ElemArtist, ElemClass, ElemLength` — строка для трека дописывается только когда придёт СЛЕДУЮЩЕЕ событие метаданных (тогда становится известна длительность предыдущего трека, `ElemLength`, формат `Ч:ММ:СС.ммм`/`М:СС.ммм`) либо когда канал останавливается (тогда недописанная строка сбрасывается на диск без `ElemLength`). **Важно**: пока трек не сменился и канал не остановлен, файл `.csv` за сегодня ещё не появится — это не баг, а отложенная запись строки (чтобы знать её длительность), так и было задумано в оригинале.

`ElemClass` — `B` для строки-разделителя тишины (пустой `ElemName`), `C` если название/исполнитель трека содержит одно из слов из `settings.yaml`/`ad_keywords` (без учёта регистра, по умолчанию «Реклама», «Reklama», «Commercial» — редактируется в диалоге «Настройки приложения», поле «Слова-маркеры рекламы»), `N` если содержит одно из слов из `settings.yaml`/`news_keywords` (без учёта регистра, по умолчанию «Новости», «News», «Novosti» — редактируется в диалоге «Настройки приложения», поле «Слова-маркеры новостей»; проверяется только если трек не попал под `C` — при совпадении с обоими списками сразу приоритет у рекламы), иначе `M` (обычная музыка).

## Настройки приложения (`config/settings.yaml`)

```yaml
log_level: INFO             # DEBUG | INFO | WARNING | ERROR
log_retention_days: 30
reconnect_delay_seconds: 3   # пауза перед повторной попыткой подключения после обрыва потока/устройства, для всех каналов
reconnect_max_attempts: 0    # после стольких неудачных подряд попыток канал останавливается и в лог пишется ERROR; 0 — не ограничивать
meter_colors:
  zone_yellow_db: -12.0
  zone_red_db: -3.0
  color_green: '#1d761d'
  color_yellow: '#ccaa00'
  color_red: '#cc1818'
ad_keywords:                 # слова-маркеры рекламы для ElemClass=C в CSV метаданных (без учёта регистра)
  - Реклама
  - Reklama
  - Commercial
news_keywords:                # слова-маркеры новостей для ElemClass=N в CSV метаданных (без учёта регистра)
  - Новости
  - News
  - Novosti
ui_language: ru               # ru | en — язык интерфейса, переключается в бургер-меню, живёт здесь между перезапусками
show_tp_indicators: false     # показывать шкалу True Peak в карточке каждого канала (см. ниже), переключается в бургер-меню и в диалоге «Настройки приложения»
auth_session_ttl_seconds: 604800   # время жизни сеанса входа (см. «Авторизация» ниже), по умолчанию неделя
```

`reconnect_delay_seconds`/`reconnect_max_attempts` применяются сразу ко всем уже запущенным каналам без перезапуска (читаются заново при каждой попытке переподключения, а не один раз при старте канала — как и `ad_keywords` выше). Если задан ненулевой предел попыток и канал его исчерпал, он останавливается сам (карточка показывает красный индикатор статуса, см. выше), в лог пишется `ERROR`, и для возобновления записи канал нужно запустить заново вручную (или он подхватится сам при следующем запуске приложения, если у него включён `auto_start`).

`show_tp_indicators` выключен по умолчанию: при `false` карточка канала не просто скрывает шкалу True Peak — она вообще не реагирует на события уровня, то есть модуль индикации в карточках не потребляет ресурсы впустую. Отдельная панель индикаторов (кнопка ▦ на карточке) от этой настройки не зависит и работает всегда.

Клик по URL источника или пути сохранения на любой карточке маскирует их звёздочками (`***`) — и делает это сразу на **всех** карточках одновременно (общий переключатель на сеанс браузера, а не отдельный на карточку), чтобы перед демонстрацией экрана не пришлось кликать по каждому каналу отдельно. Повторный клик на любой карточке возвращает исходный текст везде.

Тема оформления (светлая/тёмная) переключается в бургер-меню (☀️/🌙) и хранится в `localStorage` браузера — это настройка конкретного браузера/устройства, а не приложения, поэтому в `settings.yaml` её нет.

Строка статуса (результат последнего действия из бургер-меню — обновление конфигурации, старт/стоп всех каналов и т.п.) выводится справа от поля фильтра, а не отдельной строкой ниже, и не скрывается сама по себе — только по кнопке ✕ или когда её сменяет следующее сообщение. Пока идёт прослушка канала (▶ на карточке), в этой же строке всё время показывается «Прослушка: {имя канала}» — сначала как обратный отсчёт буферизации (секунды до появления звука, `playout_buffer_seconds`), затем как постоянная надпись, пока прослушка не остановлена.

Все диалоговые окна (подтверждения, редактирование канала, настройки и т.д.) и бургер-меню закрываются по Esc — как и клик по затемнённому фону вокруг них. Исключение — редактирование канала и массовое изменение: там ни клик по фону, ни Esc не закрывают форму, чтобы случайное нажатие не сбросило несохранённые правки.

«☑️ Массовое изменение» в бургер-меню включает режим выбора: на каждой карточке канала появляется галочка, а строка статуса сменяется кнопкой «Изменить…» (активна, когда отмечен хотя бы один канал). В открывшемся диалоге — те же поля, что и в редактировании одного канала (формат папки по дате, формат имени файла, длительность файла, срок хранения, вести запись, автозапуск, режим формата вывода, детектор тишины и его порог/время срабатывания/время возобновления), но у каждого поля своя галочка «применить» — меняются только отмеченные поля, всё остальное (источник, путь сохранения, имя и т.д.) у каждого канала остаётся как было. После применения режим выбора выключается сам.

Веб-интерфейс держит соединение с сервером (SignalR) — если вкладка браузера долго простаивала в фоне или сервер на время стал недоступен (перезапуск службы, сетевой сбой), сверху покажется баннер «⚠️ Переподключение к серверу…»; приложение само пробует восстановить соединение в течение ~1.5 минут, а если это не удаётся (например, служба реально перезапустилась и старое соединение больше не существует) — страница сама перезагрузится, вручную обновлять её не нужно.

## Авторизация (`config/ldap.yaml`)

Авторизация **по умолчанию отключена**, как и раньше — приложение открывается без запроса входа. Чтобы включить её, создайте `config/ldap.yaml`; чтобы выключить обратно — удалите файл. Схема осознанно повторяет уже существующее приложение «Абрикос» (apricot2): те же имена файлов, те же ключи, тот же порядок проверки (сначала локальные учётные записи, затем LDAP/AD). Готовые примеры всех файлов ниже (с подробными комментариями) лежат в `config.demo/ldap.yaml`/`users.yaml`/`secret.yaml` — проще скопировать и отредактировать, чем собирать с нуля.

**`config/ldap.yaml`** (пример: локальный вход + один домен AD):
```yaml
Local: true    # включить проверку по config/users.yaml
LDAP: true     # включить проверку по Active Directory

# Группы AD с правами администратора — участники get IsAdmin (пока ничего в UI не ограничивает,
# кроме самого факта входа; задел на будущее разделение прав)
admin_groups:
  - "CN=RadioAdmins,OU=Groups,DC=corp,DC=local"

# Если задать непустым — входить смогут только участники этих групп (остальные аутентифицированные
# доменные пользователи получат отказ). Пусто/не задано — как в apricot2: входит любой, кто прошёл
# аутентификацию в одном из доменов ниже.
# access_groups:
#   - "CN=RadioUsers,OU=Groups,DC=corp,DC=local"

server: "ldap://dc01.corp.local"
domain: "CORP"
base_dn: "DC=corp,DC=local"
bind_secret: 10   # опционально — id сервисного аккаунта из config/secret.yaml для поиска пользователя по имени

# Несколько доменов — вместо server/domain/base_dn/bind_secret выше:
# domains:
#   - name: "CORP"
#     server: "ldap://dc01.corp.local"
#     base_dn: "DC=corp,DC=local"
#     bind_secret: 10
```

`Local`/`LDAP` — единственные два ключа, которые пишутся с заглавных букв (как в apricot2); всё остальное — строчными, как и везде в конфигах Айвы. Формат имени пользователя на странице входа: `ivanov` (перебор всех настроенных доменов), `CORP\ivanov` (только домен с `name: CORP`), `ivanov@corp.local` (только домен с таким UPN-суффиксом, выводится из `base_dn` или задаётся явно полем `upn_suffix`).

**`config/users.yaml`** (локальные учётные записи, нужен только при `Local: true`):
```yaml
users:
  - username: admin
    password_hash: "$2a$11$..."   # BCrypt-хэш, см. ниже
    is_admin: true
```
Хэш пароля генерируется без вспомогательных скриптов — прямо самим exe:
```
Quince.Service.exe --hash-password
```
Если `Local: true`, а `config/users.yaml` отсутствует, при каждом запуске генерируется случайный одноразовый пароль для пользователя `admin` и выводится в лог (`[WARNING] ... логин: admin  пароль: ...`) — временная мера, не для постоянного использования.

**`config/secret.yaml`** (опционально — сервисный аккаунт для поиска пользователя перед проверкой его пароля; без него используется прямой bind под учётными данными самого входящего):
```yaml
authorization:
  - id: 10
    username: "ldap"
    password: "ldap-service-password"
    domain: "CORP"
```

Сеансы входа хранятся в памяти и дублируются в `config/sessions.yaml`, поэтому переживают перезапуск приложения/службы — не нужно логиниться заново после каждого обновления версии. Время жизни сеанса — `auth_session_ttl_seconds` в `settings.yaml` (по умолчанию неделя).

## Журнал (`log/`)

- Новый файл каждый день: `log/YYYY-MM-DD.log`.
- Уровень логирования настраивается через `log_level` в `app.yaml` (DEBUG/INFO/WARNING/ERROR).
- Старые файлы удаляются автоматически по истечении `log_retention_days` дней (по умолчанию 30).
- Формат строки: `YYYY-MM-DD HH:MM:SS.mmm [LEVEL] [channel_name] сообщение` — `[channel_name]` заменяется на `[-]` для сообщений уровня приложения, не привязанных к конкретному каналу.

## Сторонние бинарные компоненты

Всё нужное для работы бандлируется прямо в `release/<версия>/` — отдельно ничего скачивать и ставить не нужно. Два сторонних бинарника (для сетевых потоков — захват со звуковой карты идёт через управляемую библиотеку NAudio, без отдельных нативных файлов):

| Файл | Расположение | Источник | Лицензия |
|---|---|---|---|
| `ffmpeg.exe` | `Quince.Service/tools/` | официальная статическая сборка [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) (`essentials_build`) | GPL/LGPL (FFmpeg) — свободное использование, в т.ч. коммерческое |
| `ffprobe.exe` | `Quince.Service/tools/` | сборка того же семейства gyan.dev `essentials_build` | GPL/LGPL (FFmpeg) — свободное использование, в т.ч. коммерческое |
| `ucrtbase.dll` + 14×`api-ms-win-crt-*.dll` (Universal C Runtime) | `Quince.Service/redist/ucrt/` | скопированы с машины разработки (`C:\Windows\System32` / `System32\downlevel`) | Microsoft — официально документированный способ «app-local deployment» UCRT; нужны на Windows без встроенной UCRT (Windows 7 SP1/8/8.1 без KB2999226/VC++ Redistributable) — без них self-contained-сборка падает с ошибкой «api-ms-win-crt-runtime-l1-1-0.dll is missing» при запуске |

Захват со звуковой карты (`SoundcardCapture`) реализован через [NAudio](https://github.com/naudio/NAudio) (MIT — свободное использование, включая коммерческое, без каких-либо оговорок) поверх WASAPI; отдельного нативного файла для этого не требуется — NAudio подключается как обычный NuGet-пакет и попадает в сборку вместе с остальными управляемыми зависимостями.

Обновление/замена `ffmpeg.exe`/`ffprobe.exe` — просто перезапись файла тем же именем в той же папке (оба подключаются по пути, а не встраиваются в сборку .NET), рестарт приложения подхватит новую версию.

**`tools/Find-Replace.ps1`** — рекурсивный поиск-замена литерального текста (не regex) во всех файлах папки. Кодировка каждого файла определяется автоматически по BOM (или UTF-8 без BOM по умолчанию) и сохраняется при записи; двоичные файлы (обнаружен нулевой байт) пропускаются, чтобы не повредить их. Поддерживает стандартные `-WhatIf`/`-Confirm` для предпросмотра без реальной записи.
```powershell
.\tools\Find-Replace.ps1 -Find 'localhost:5000' -Replace 'localhost:8080' -Path C:\Quince\config

# Предпросмотр без изменения файлов
.\tools\Find-Replace.ps1 -Find 'старое' -Replace 'новое' -Path .\config -WhatIf
```

## Вспомогательные скрипты (`Quince.Service/scripts/`)

Отдельные PowerShell-скрипты для разового/периодического обслуживания — не часть самого приложения, не собираются и не публикуются вместе с `Quince.Service.exe`. Запускаются вручную из папки `Quince.Service/scripts/` (или с указанием полного пути).

- **`Import-RadioPlayerStations.ps1`** — загружает список московских радиостанций с API `radioplayer.ru`, обновляет справочный файл `MOSCOW.md` (таблица «станция → stream URL → metadata URL») и опционально создаёт готовые YAML-конфиги каналов в `config/stations/`.
  ```powershell
  # Только обновить MOSCOW.md
  .\scripts\Import-RadioPlayerStations.ps1

  # Создать YAML-конфиги для всех найденных станций с потоком
  .\scripts\Import-RadioPlayerStations.ps1 -CreateConfigs

  # Указать другую папку конфигов
  .\scripts\Import-RadioPlayerStations.ps1 -CreateConfigs -ConfigDir "D:\quince\config\stations"

  # Только станции, в названии которых встречается подстрока
  .\scripts\Import-RadioPlayerStations.ps1 -CreateConfigs -Filter "Ретро FM"
  ```
  Существующие файлы конфигов не перезаписываются (совпадение по имени файла — пропускаются с пометкой в выводе). Сгенерированные конфиги содержат поле `source.reconnect_delay_seconds` — устаревшее с версии 0.00.025 (задержка переподключения теперь только в общих настройках приложения, см. «Настройки приложения» выше); `YamlConfigLoader` игнорирует незнакомые поля при загрузке, так что это не мешает, но и не используется — можно смело убрать при ручной правке.

- **`Convert-ToApricot.ps1`** — конвертирует уже существующие YAML-конфиги каналов Айвы в формат другого приложения, «Абрикос» (`stations/<GroupId>.yaml` + `playlogs/*.yaml`). Не требует внешних модулей — использует собственный минимальный YAML-парсер (только плоские `key: value` и один уровень вложенности, этого достаточно для схемы конфига канала Айвы).
  ```powershell
  .\scripts\Convert-ToApricot.ps1 -InputDir C:\Logger\config -OutputDir C:\Abricot\config
  .\scripts\Convert-ToApricot.ps1 -InputDir config -Filter 'Европа' -GroupId msk-hls -GroupName 'Москва HLS'
  ```
  `-InputDir` понимает и полный путь, и путь, введённый относительно текущей папки, — а если такого пути там нет, скрипт дополнительно пробует относительно своей собственной папки и относительно её родителя (это покрывает типичный случай, когда `config\` лежит рядом со `scripts\`, как в этом репозитории, — просто `-InputDir config` срабатывает независимо от того, откуда запущен скрипт). `-OutputDir` по умолчанию — `<InputDir>\apricot_export`. `-GroupId`/`-GroupName` — верхнеуровневые `id`/`name` итогового файла станций (по умолчанию — имя папки `-InputDir`). Результат: один файл `stations/<GroupId>.yaml` с массивом `channels:` — по одному элементу на каждый канал (SMB-путь и хост экспортируются с плейсхолдерами `LOGGER-HOST`/`LOGGER`, требуют ручной правки), и для каждого канала с настроенными метаданными — отдельный файл в `playlogs/<id>.yaml` (маппинг на CSV-колонки Айвы: `EventTime`/`ElemName`/`ElemArtist`/`ElemClass`).

- **`MOSCOW.md`** — не скрипт, а результат работы `Import-RadioPlayerStations.ps1`: таблица-справочник по московским станциям radioplayer.ru, используется как источник данных при добавлении новых каналов вручную.

## Известные ограничения (по состоянию на 0.00.021)

- Папка `config/RP/` (~150 доп. станций) не читается рекурсивно — обрабатываются только файлы верхнего уровня `config/stations/`.
