# Айва (Quince.Service) — техническое задание

> Документ описывает ТЗ на разработку — то есть целевое поведение системы,
> а не хронологию правок. Хронология и обоснования конкретных решений —
> в `docs/HISTORY.md` (дословные запросы + ответы) и `docs/CHANGELOG.md` (по версиям). Инструкции по
> установке и эксплуатации — в `README.md`. Этот файл не дублирует их, а фиксирует целостную картину
> того, что должно быть реализовано.

## 1. Назначение

Многоканальный аудиологгер для непрерывной записи интернет-радиостанций (потоковых источников) и
локальных звуковых карт на диск, с распознаванием метаданных треков, контролем уровня и тишины,
веб-интерфейсом управления и опциональной авторизацией. Заменяет собой легаси-приложение на
PyQt6 + Python («Абрикос» / apricot2), сохраняя визуальный язык и часть архитектурных решений
(схема авторизации, разметка карточек, работа с YAML-конфигами), но переписан на ASP.NET Core
Blazor Server и работает как служба Windows.

## 2. Технологический стек

- .NET 8, `net8.0-windows`, self-contained публикация под `win-x64` (рантайм и все зависимости — в
  папке публикации, на целевой машине ничего дополнительно ставить не нужно, кроме UCRT на
  Windows 7/8/8.1 — см. `redist/ucrt`).
- ASP.NET Core **Blazor Server** (SignalR-based interactive UI) + Razor Pages (страница логина,
  `_Host.cshtml`).
- `Microsoft.Extensions.Hosting.WindowsServices` — установка и работа как служба Windows
  (`ServiceName = "QuinceAudioLogger"`), рабочая директория службы (обычно `System32`) не участвует
  в резолвинге путей — все пути анкерятся к `AppContext.BaseDirectory` (`PathResolver.cs`).
- `YamlDotNet` — конфигурация целиком в YAML, underscored naming convention.
- `NAudio` (WASAPI, shared-mode) — захват со звуковой карты.
- Внешний `ffmpeg.exe`/`ffprobe.exe` (бандл в `tools/`) — декодирование потоков (Icecast/HLS),
  кодирование в выходной формат при записи на диск, транскодирование в MP3 для прослушки в браузере.
- `System.DirectoryServices.Protocols` — LDAP/AD.
- `BCrypt.Net-Next` — хэширование локальных паролей.
- `Markdig` — рендер `README.md` в диалоге «Показать README».
- Self-hosted шрифт Nunito (все начертания, кириллица+латиница, `wwwroot/fonts/`).

## 3. Архитектура: поток аудио

```
Источник (URL потока | звуковая карта)
        │
        ▼
IAudioCapture (StreamCapture — ffmpeg-субпроцесс | SoundcardCapture — NAudio WASAPI)
        │  сырые PCM-чанки (44100Hz/2ch float), publish/subscribe на нескольких подписчиков
        ├──────────────► AudioWriter (если запись включена) ──► файл на диске (свой кодек/ротация)
        ├──────────────► SilenceDetector ──► события SOUND/SILENT
        └──────────────► PlayoutBuffer (джиттер-буфер, ~12с по умолчанию)
                                │
                                ├──► LevelMeter ──► True Peak / LUFS M,S,I / гониометр ──► UI
                                └──► (по запросу) AudioStreamEndpoint ──► ffmpeg→MP3 ──► браузер (▶)
```

Ключевой принцип: **джиттер-буфер стоит только на пути к человеку** (индикаторы, прослушка) —
запись на диск и детектор тишины всегда работают на сыром, небуферизованном потоке, чтобы
сглаживание пауз источника не искажало ни сам файл, ни срабатывание тишины.

`ChannelEngine` — оркестратор одного канала, собирает пайплайн выше из конфигурации канала;
`AudioEngineManager` (`IHostedService`) — реестр живых `ChannelEngine` на всё приложение, авто-старт
каналов с `auto_start: true`, реагирует на изменения конфигурации «на лету» (перезапускает движок
только если менялось что-то, влияющее на пайплайн; косметические поля применяются без рестарта).

## 4. Функциональные требования

### 4.1 Управление каналами

- Создание, редактирование, клонирование, удаление канала через веб-форму (`ChannelEditDialog`).
- Один канал = один YAML-файл в `config/stations/`; имя файла генерируется из имени канала с
  защитой от коллизий (`ChannelManager.GenerateFilename`).
- Ре-сканирование папки конфигов «на лету» (пункт меню «Обновить конфигурацию») без перезапуска
  приложения — диффит on-disk состояние с in-memory и рассылает Added/Updated/Removed.
- Клонирование отключает `auto_start` у копии (не запускать два движка на один источник сразу).
- **Массовое изменение** (см. 4.10) — применение одинаковых настроек к нескольким каналам разом.

### 4.2 Источники аудио

Два типа (`source.type`):

- **`stream`** — Icecast или HLS (`.m3u8`). Настройки: URL, тип потока, индекс аудиодорожки для
  HLS (мульти-битрейтные плейлисты), разрешить HTTP без TLS, игнорировать невалидный SSL-сертификат,
  URL/режим метаданных. Захват — субпроцесс `ffmpeg`, с эвристикой рассинхронизации «URL похож на
  HLS, а тип выставлен другой» (предупреждение в форме редактирования, не блокирует сохранение).
- **`soundcard`** — локальное устройство записи (WASAPI, shared-mode). Выбор устройства по UID (в
  приоритете), имени, индексу, либо устройство по умолчанию. Список устройств и обновление —
  прямо в форме редактирования канала.

Общая логика подключения (для обоих типов): счётчик попыток переподключения сбрасывается **только
после подтверждённого приёма реальных данных**, а не при одном лишь успешном старте процесса/API —
иначе постоянно недоступный источник переподключается бесконечно вопреки лимиту попыток.

### 4.3 Запись на диск

- Формат вывода — «как во входном потоке» (кодек/контейнер выбираются по фактическому источнику:
  WAV для звуковой карты, AAC для HLS, MP3 для Icecast) либо «свой формат» (MP3/AAC/WAV, битрейт,
  битность, частота дискретизации, число каналов — на выбор).
- Ротация файлов по `file_duration_minutes`, границы выровнены по часовой сетке от полуночи, плюс
  принудительная ротация на смене календарной даты.
- Путь сохранения: `save_path/{дата по date_folder_format}/{время по file_name_format}.{ext}`.
- Автоочистка: файлы и пустые папки старше `retention_days` удаляются при старте и на каждой смене
  даты.
- `record_audio` — можно завести канал только для прослушки/индикации, без записи на диск.
- `auto_start` — автозапуск при старте приложения.

### 4.4 Индикация уровня

- True Peak (dBTP, 4x oversampling) и LUFS Momentary/Short-term/Integrated (K-weighting,
  EBU R128 / ITU-R BS.1770-4) — на каждой карточке (упрощённый TP) и в развёрнутой панели
  индикаторов канала (▦ — полный набор + гониометр).
- Гониометр — Lissajous-скаттер L/R в реальном времени, `<canvas>`, decimated до ≤256 точек на кадр.
- Индикаторы канала на карточках — **опциональны**, управляются общей настройкой (по умолчанию
  выключены): при выключении карточка не просто скрывает шкалу, а вообще не подписывается на
  события уровня для неё — модуль индикации в карточках не выполняет работу впустую.
- Пиковые значения в развёрнутой панели держатся до явного сброса кликом (не сбрасываются сами при
  паузах/перезапуске движка).
- Цветовые зоны шкалы (жёлтая/красная, пороги в dBFS) настраиваются в общих настройках приложения.

### 4.5 Детектор тишины

Опциональный, на канал: порог (dBFS), время срабатывания и время возобновления (секунды). Работает
на сыром потоке (не через джиттер-буфер). Статус (SOUND/SILENT) отражается на карточке отдельным
индикатором; при отсутствии детектора карточка не показывает ложное состояние — только «нет
сигнала совсем», если канал реально не может подключиться (счётчик переподключений > 0).

### 4.6 Метаданные

- **ICY** (Icecast, `icy-metaint`) — инлайн-протокол, разбор `StreamTitle=`, экспоненциальный
  backoff при ошибках, не переживает отсутствие `icy-metaint` в ответе сервера.
- **HLS** — поиск JSON-эндпоинта метаданных рядом с плейлистом (несколько кандидатных путей),
  опциональный фолбэк на `ffprobe`-пробу ID3-тегов, поллинг раз в 5 секунд одним переиспользуемым
  `HttpClient` на весь сеанс (не новым на каждый опрос — иначе просадка синхронизируется по всем
  каналам разом).
- Автоопределение доступности метаданных — отдельная кнопка в форме редактирования канала.
- Результат — CSV-лог по датам (`EventTime,ElemName,ElemArtist,ElemClass,ElemLength`, UTF-8 BOM),
  строка предыдущего трека дописывается только по приходу следующего события (тогда известна
  длительность). `ElemClass`: `C` — реклама (по списку слов-маркеров), `N` — новости (по списку
  слов-маркеров, проверяется после рекламы), `B` — тишина/разделитель, `M` — музыка (по умолчанию).
  Списки слов-маркеров редактируются в общих настройках и применяются «на лету».

### 4.7 Реконнект и статус

- Пауза между попытками и предел попыток — общие настройки, применяются ко всем уже запущенным
  каналам без перезапуска (читаются заново на каждой попытке, не кэшируются при старте канала).
- Исчерпание лимита — канал останавливается сам, статус «Ошибка» (красный индикатор), ERROR в лог;
  возобновление — вручную или при следующем старте приложения (если `auto_start`).
- Карточка канала показывает: точку записи (зелёная/красная/пульсирующая жёлтая при
  переподключении), точку метаданных (для потоковых источников), точку «звук есть/тишина/нет
  соединения», подпись «Реконнект #N» рядом с именем.

### 4.8 Прослушка в браузере

- Кнопка ▶ на карточке — транслирует канал в браузер пользователя (текущее аудиоустройство вывода
  ОС по умолчанию; выбор устройства вывода не реализован — требует `setSinkId()`/HTTPS).
- Если канал не был запущен — стартует автоматически только для прослушки (без записи на диск),
  и останавливается вслед за остановкой прослушки, если не был запущен независимо.
- Статус-строка: во время буферизации — анимированный Brailleспиннер с обратным отсчётом (секунды
  до появления звука, из настройки задержки джиттер-буфера); как только звук реально пошёл —
  постоянная надпись «Прослушка: {канал}», которая не исчезает сама, пока прослушка не остановлена.

### 4.9 Веб-интерфейс

**Список каналов** — карточки (фильтр по имени над списком), у каждой: статус-точки, имя,
кнопки Старт/Стоп записи, ▶ прослушки, ✎ редактировать, ⧉ клонировать, ▦ индикаторы, ✕ удалить;
строки «Вход:»/«Файл:» с кликабельным маскированием чувствительных значений (URL, путь) —
маскирование общее на все карточки сразу (один клик скрывает/показывает на всех), не отдельно на
карточку.

**Бургер-меню** (шапка): новый канал, старт/стоп всех каналов, обновить конфигурацию, показать/
скрыть индикаторы уровня в карточках, массовое изменение, настройки приложения, README, вход/выход
(если включена авторизация), тема оформления, язык интерфейса, о программе. Переключатели темы,
языка и индикаторов уровня **не закрывают меню** по клику (можно переключить несколько подряд);
остальные пункты — обычные разовые действия, закрывают меню.

**Тема оформления** — светлая/тёмная, переключатель в бургер-меню, хранится в `localStorage`
браузера (настройка устройства, не приложения — не в `settings.yaml`). Реализована через CSS custom
properties с `[data-theme="dark"]`-переопределением; применяется до первой отрисовки (инлайн-скрипт
в `_Host.cshtml`), без миганий. Статусные цвета (индикаторы записи/ошибки, жёлтая шапка-бренд,
цветные плашки-подсказки) одинаковы в обеих темах — меняются только фон, поверхности, границы и
текст.

**Язык интерфейса** — RU/EN, плоские JSON-словари (`i18n/ru.json`, `i18n/en.json`), общая настройка
приложения (не per-браузер), переключается вживую без перезагрузки страницы.

**Диалоговые окна** и бургер-меню закрываются по Esc (как и клик по затемнённому фону вокруг них),
кроме форм с несохраняемым вводом (редактирование канала, массовое изменение) — там ни фон, ни Esc
не закрывают, чтобы случайное нажатие не потеряло правки.

**Статус-строка** — результат последнего действия из меню, справа от поля фильтра (не отдельной
строкой ниже), не скрывается сама по себе (только по ✕ или пока её не сменит следующее сообщение).

### 4.10 Массовое изменение

Режим выбора нескольких каналов галочками на карточках (бургер-меню → «Массовое изменение»); пока
активен — строка статуса заменяется кнопками «Выбрать все» (учитывает текущий фильтр по имени),
«Снять все отметки», «Изменить…» (активна только если отмечен хотя бы один канал). Диалог
применения — те же поля, что при редактировании одного канала: формат папки по дате, формат имени
файла, длительность файла, срок хранения, вести запись, автозапуск, режим формата вывода, детектор
тишины (вкл/выкл, порог, время срабатывания, время возобновления) — но у каждого поля отдельная
галочка «применить»: меняются только отмеченные поля, всё остальное у каждого канала (источник,
путь, имя и т.д.) остаётся как было, применяется поверх собственной текущей конфигурации каждого
канала, а не единым шаблоном. После применения режим выбора выключается сам.

### 4.11 Настройки приложения (`settings.yaml`)

Уровень и срок хранения логов, пауза/предел попыток переподключения, задержка джиттер-буфера,
цветовые зоны индикатора (пороги + цвета), слова-маркеры рекламы/новостей, язык интерфейса,
показывать ли индикаторы уровня в карточках, срок жизни сессии входа. Редактируются в диалоге
«Настройки приложения», применяются вживую без перезапуска.

### 4.12 Авторизация

- Выключена по умолчанию (нет `config/ldap.yaml` — открытый доступ, как раньше).
- Схема — по образцу легаси-приложения apricot2: `ldap.yaml` содержит переключатели `Local`/`LDAP`;
  при включённой авторизации сначала проверяются локальные учётные записи (`users.yaml`, BCrypt),
  затем LDAP/AD.
- LDAP: простой bind по UPN (не NTLM), однодоменная или мультидоменная конфигурация, разбор логина
  в форме `DOMAIN\user`/`user@domain`/без домена, транзитивное разрешение вложенных групп AD
  (`LDAP_MATCHING_RULE_IN_CHAIN`) + первичная группа пользователя, опциональный двухфазный bind
  через сервисный аккаунт (`secret.yaml`) для поиска пользователя/групп перед проверкой его
  собственного пароля. `admin_groups` даёт права администратора, `access_groups` (если задан)
  ограничивает вход только участникам перечисленных групп.
- Разбор ошибок входа — раздельные понятные сообщения: неверный пароль, пользователь не найден,
  не входит в разрешённую группу, ошибка конфигурации LDAP (не задан сервер/база, не прошёл
  аутентификацию сервисный аккаунт), и отдельно — сетевая недоступность сервера AD (таймаут, сервер
  недоступен, DNS) как отличная от «неверно настроен bind-аккаунт».
- Сессии — токен в HttpOnly-cookie, in-memory реестр, персистится в `sessions.yaml` (переживает
  перезапуск процесса/службы), TTL из общих настроек.
- Если `users.yaml` пуст, а локальный вход включён — одноразовый случайный пароль администратора
  генерируется и пишется в лог с предупреждением создать постоянный файл.
- Утилита `Quince.Service.exe --hash-password` — интерактивно генерирует BCrypt-хэш для
  `users.yaml`.

### 4.13 Логирование

Собственный файловый провайдер `ILogger` — ежедневная ротация (`log/{дата}.log`), формат строки
`timestamp [LEVEL] [канал] сообщение`, фильтрация по уровню и автоочистка по сроку хранения — оба
параметра меняются вживую из настроек приложения.

### 4.14 Установка как служба Windows

Готовые bat-скрипты (`tools/service-*.bat`) с самоповышением прав (UAC) для создания, запуска,
остановки, перезапуска и удаления службы через `sc.exe`. Все пути (конфиги, логи, инструменты)
резолвятся от папки exe, а не от рабочей директории службы. Приложение **не имеет собственного
пункта меню «перезапуск»** — обновление версии выполняется штатно: остановить службу, заменить
файлы публикацией, запустить снова.

## 5. Модель конфигурации

Все данные — рядом со скомпилированным `Quince.Service.exe`, вне git (`config/` в `.gitignore`,
шаблон с фиктивными значениями и подробными комментариями — в `config.demo/`, копируется в
публикацию так же, как и `config/`).

| Файл | Назначение |
|---|---|
| `config/settings.yaml` | Общие настройки приложения — см. 4.11 |
| `config/stations/*.yaml` | По одному файлу на канал записи — см. 4.1–4.5 |
| `config/ldap.yaml` | Переключатель и параметры авторизации — см. 4.12; отсутствие файла = авторизация выключена |
| `config/users.yaml` | Локальные учётные записи (BCrypt-хэши) |
| `config/secret.yaml` | Сервисные учётные записи для LDAP bind (опционально) |
| `config/sessions.yaml` | Активные сессии входа (управляется приложением, не редактируется руками) |

Все файлы — YAML, underscored naming (`snake_case` ключи), парсер терпим к отсутствующим/лишним
полям и умеет мигрировать устаревшие названия ключей на лету (например, старый `app.yaml` →
`settings.yaml`, `file_duration_seconds` → `file_duration_minutes`).

## 6. Нефункциональные требования

- **Производительность под нагрузкой**: рассчитано на 15–30 одновременно работающих каналов
  (~5–7 фоновых задач на каждый — захват, запись, метр уровня, детектор тишины, чтение метаданных,
  опрос состояния); минимальный размер пула потоков поднят заранее (`ThreadPool.SetMinThreads`),
  чтобы не проседать индикаторами и прослушкой при всплесках готовых продолжений.
- **Развёртывание**: self-contained публикация, без внешних зависимостей от .NET на целевой
  машине; работает и как обычный процесс, и как служба Windows без правок кода.
- **Устойчивость к сбоям источника**: реконнект с настраиваемой паузой/лимитом, watchdog зависания
  ffmpeg (таймаут на отсутствие байт от процесса), джиттер-буферизация периодических пауз источника
  (характерно для HLS) — не искажает ни запись на диск, ни детектор тишины.
- **Безопасность**: пароли — только BCrypt-хэши на диске, сессионные cookie — HttpOnly; чувствительные
  значения (URL источника, путь сохранения) можно скрыть на экране одним кликом перед демонстрацией.
- **Локализация**: полный охват UI-текста (не логов/метаданных/имён полей конфига) — RU/EN.
- **Совместимость**: визуальный язык и часть конфигурационной схемы намеренно повторяют легаси
  apricot2 (шрифт, палитра, разметка карточек, авторизация) для плавного перехода эксплуатации.

## 7. Тестирование

Модульные тесты (xUnit, `Quince.Service.Tests`) — чистая бизнес-логика без реальной сети/устройств/
ffmpeg: выбор параметров кодирования, разбор метаданных (HLS JSON/ICY), True Peak/LUFS-расчёты,
K-weighting фильтр, детектор тишины, джиттер-буфер, выбор устройства записи, генерация имён файлов,
миграции конфигов, вспомогательные форматтеры UI. Живая проверка (реальный запущенный процесс,
реальные каналы, браузер) — вручную/через Playwright перед каждым релизом, отдельно от модульных
тестов; фиксируется в `docs/HISTORY.md` по каждому пункту.

## 8. Известные ограничения (вне рамок текущей реализации)

- Выбор устройства аудиовывода для прослушки в браузере — не реализован (требует `setSinkId()` и
  HTTPS).
- Вход со звуковой карты не проверялся на реальном разнообразии оборудования, только модульными
  тестами логики выбора устройства.
- Собственного механизма перезапуска приложения из UI нет (см. 4.14) — обновление и перезапуск
  выполняются администратором вручную через `sc.exe`/bat-скрипты.
- Массовое изменение работает только с полями, перечисленными в 4.10 — источник, путь сохранения,
  имя канала бульк-редактированием не меняются (осознанно, во избежание коллизий имён/путей при
  массовом применении).
