# Changelog

Формат версии: `X.YY.ZZZ`. Патч (`ZZZ`) увеличивается на 1 при каждой доработке; старшие номера (`X`, `YY`) меняются только по явной команде пользователя.

## 0.00.003 — защита обработчиков событий в AudioEngineManager

- Исправлена критическая уязвимость: `PushLevel` и `PushStatus` теперь оборачивают вызовы событий в try/catch с логированием. Конкретный риск: если обработчик события в `ChannelCard` выбросит исключение (например, `InvokeAsync` на разорванном Blazor-circuit), исключение распространялось бы из `ChannelEngine.MonitorAsync` или `SilenceDetector.RunAsync`, молча убивая background-task этого канала навсегда без логирования. Теперь все исключения отловлены и залогированы.

## 0.00.002 — аудио-движок для stream-каналов

- Реализован полный конвейер записи для каналов `source.type: stream` (Icecast/HLS): `StreamCapture` (ffmpeg-подпроцесс, декодирование, реконнект), `AudioWriter` (ротация по временной сетке, retention), `LevelMeter` (True Peak + LUFS, EBU R128), `SilenceDetector`.
- Новый `AudioEngineManager` (`IHostedService`) управляет движком по каналам, авто-старт для `auto_start: true`.
- UI: кнопка Старт/Стоп теперь реально запускает/останавливает запись, статус-точки и индикатор уровня отражают реальное состояние — напрямую через in-process C#-события `AudioEngineManager` (`LevelUpdated`/`StatusUpdated`) на каждую `ChannelCard`, без отдельного SignalR-хаба: обновление UI обеспечивает штатный circuit самого Blazor Server. Для каналов `soundcard` кнопка задизейблена — этот тип источника ещё не реализован.
- Забандлен `ffmpeg.exe` в `Quince.Service/tools/` (официальная статическая сборка), путь настраивается через `FfmpegPath`.
- Добавлен проект `Quince.Service.Tests` (xUnit) с покрытием чисто логических частей движка.

**Известные ограничения**: звуковая карта (`source.type: soundcard`) и метаданные потока (ICY/HLS — название трека) всё ещё не реализованы; окно индикаторов (▦) и редактирование/клонирование/удаление канала остаются визуальными заглушками.

## 0.00.001 — первая версионированная сборка

- Первый рабочий каркас `Quince.Service` (ASP.NET Core Blazor Server + SignalR, Windows Service).
- Исправлены проблемы окружения: закреплены версии `ManagedBass`/`ManagedBass.Mix` (3.1.0), добавлен отсутствовавший `Pages/_Imports.razor`.
- Конфиги каналов: устранена коллизия папок `Config`/`config` на регистронезависимой ФС — исходники перенесены в `Configuration/`, реальные данные — в `Quince.Service/config/` (копируются в выходную папку сборки при билде).
- Путь к папке конфигов и логов теперь анкерится к папке скомпилированного приложения (`AppContext.BaseDirectory`), а не к рабочей директории процесса — одинаково работает при `dotnet run`, прямом запуске `.exe` и как установленная служба Windows.
- `ChannelConfig` полностью переписан под реальную схему YAML легаси-приложения (`source`, `input_format`, `output_format`, `silence_detector` и т.д.); файлы без `name` (например `app.yaml`) больше не грузятся как «пустой канал».
- Веб-интерфейс: карточки каналов, повторяющие визуальный язык легаси-приложения на PyQt6 (статус-точки, кнопки Старт/✎/⧉/▦/✕, строки «Вход:»/«Файл:», плейсхолдер индикатора уровня).
- Header с бургер-меню (структура и логика — по образцу `apricot2`), пункты меню перенесены из легаси `main_window.py`; полностью скопированы размеры/шрифты (self-hosted Nunito) apricot2, иконка и цветовая палитра — на основе `quince/assets/icon.svg` (светло-жёлтый).
- Логирование: `Configuration/AppConfig.cs` (модель `app.yaml`), `Services/FileLoggerProvider.cs`/`FileLogger.cs` — файловый провайдер `ILogger` с ежедневной ротацией (`log/YYYY-MM-DD.log`), очисткой по сроку хранения, фильтрацией по уровню и точным форматом строки `YYYY-MM-DD HH:MM:SS.mmm [LEVEL] [channel_name] сообщение`.
- Заведено версионирование (`VersionInfo.cs`), `HISTORY.md`, `CHANGELOG.md`, `README.md`, публикация сборки в `release/`.

**Известные ограничения**: движок записи аудио (`ManagedBass`) не реализован — кнопки Старт/Стоп и большинство пунктов меню визуальные; живые индикаторы уровня и события ротации/переподключения/детектора тишины в лог пока не пишутся, т.к. нет реального аудио-пайплайна.
